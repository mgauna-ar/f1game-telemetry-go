# F1 Game Telemetry Project Rules

Architectural boundaries, invariants, and verification gates for this repo.

## 1. Mandatory Verification & Testing
* **Pre-Completion Gate:** NEVER mark a task complete without passing all checks below:
  1. **Go Format & Linters:** `gofmt -l .`, `go vet ./...`, `golangci-lint run` (0 issues).
  2. **Generated Wire Types:** `go run ./cmd/tsgen -check` (0 stale; regenerate via `make gen-types`; checked by `TestGeneratedFilesUpToDate`).
  3. **Go Backend Tests:** `go test -race -count=1 ./...` from root (100% pass without cache; table-driven tests for parsers/errors).
  4. **Frontend Lint:** `npm run lint` (`oxlint` + `jsx-a11y`) in `frontend/` (0 errors).
  5. **Frontend Tests:** `npm test` (`vitest run` with `@testing-library/react` + `jsdom`) in `frontend/` (100% pass).
  6. **Production Build:** `npm run build` in `frontend/` (`tsc -b && vite build`, 0 errors).
  7. **Reporting:** Report actual test counts, linter status, and build results in the final response.
* **UDP Simulator (`cmd/simulator`) & Helpers:**
  - `make simulate` (2026: 22 cars + 2 observers; `FORMAT=2025`: 20 + 2) or `simulate.bat` sends every packet type at 20Hz (`CarTelemetry2` for 2026).
  - Scenarios (`-scenario <name>`): `wear`, `sc`, `vsc`, `rain`, `start`, `pit`. `run.bat` builds and launches the embedded Windows binary.

## 2. Clean Code, Constants & Principles
* **Zero Magic Numbers / Literals:** Never hardcode numeric literals, status codes, or hex colors in Go/TS (packet IDs, statuses, safety car modes, weather, compounds, time conversions, ERS energy, buffer sizes, colors).
* **Go Constants:** `internal/packets/constants*.go` as `packets.*` (`ResultStatusFinished`, `PitStatusPitting`, `MillisPerMinute`, `MaxERSStoreEnergyJoules`, `DefaultTelemetrySampleCapacity`, `DriverName(...)`, `TeamName(...)`, `SessionTypeName(...)`).
* **Frontend Constants:** `frontend/src/constants/f1.ts` (`PACKET_IDS`, `RESULT_STATUS`, `PIT_STATUS`, `DRIVER_STATUS`, `SAFETY_CAR_STATUS`, `PENALTY_TYPES`, `WEATHER_CODES`, `SESSION_TYPES`, `TIME_CONSTANTS`, `ACTIVE_AERO_MODES`, `SESSION_DATA_CACHE_LIMIT`).
* **Principles:** **DRY** (reuse constants, wire types, helpers, hooks), **Separation of Concerns** (thin HTTP handlers; domain logic in `internal/{analytics,session,engineer}`; presentation in React + Zustand), **KISS & YAGNI** (direct, testable code over speculative abstractions).

## 3. Technology Stack & Architecture
* **Platform & Spec:** Windows 10/11, macOS, Linux. Exclusive to **F1 2025** & **F1 2026 DLC** UDP (`PacketFormat` 2025/2026, 29-byte `PacketHeader`; ≤2023 deprecated). Vite (`frontend/dist`) embeds via `//go:embed` (`frontend/embed.go`), served with SPA fallback (`setupStaticRoutes` in `internal/api/server.go`) + `system.OpenBrowser`.
* **Backend Packages (`internal/`):**
  - `api/`: HTTP router, decoding, middleware, serialization only (**zero domain/analytical logic**). Enforces `http.CrossOriginProtection`, no CORS headers, `MaxJSONBodyBytes` (2 MB) on `/api`, `MaxImportPayloadSize` (100 MB) on `POST /api/sessions/import`.
  - `udp/`: Non-blocking UDP listener (`Listener`).
  - `packets/`: 1:1 binary UDP decoders/constants. **Gotcha:** in `PacketLapData`, `LapDistance` and `TotalDistance` (`float32`) sit right before `SafetyCarDelta`.
  - `session/`: `SessionManager`, `LapTracker`, `TelemetryBatchWriter`, `LiveBroadcaster` (10 Hz `LiveSnapshot` + `FeedEvent`), ZIP import/export.
  - `analytics/`: Standings, `MergeLapComparisonCached` (5m grid), progression matrices, stint degradation OLS regression, `TrackProgressResponse`, `ChatContextSource` (`ai.RecordedRaceSource`).
  - `engineer/`: Strategy engine (`EngineerEngine`, `EngineerRule`), race history (player laps, rival histories, events, radio calls), live context (`RaceContext()`, `LiveBriefing()` as `ai.LiveRaceSource` at `GET /api/ai/engineer/race-context`), `RaceTools()` (`race_tools*.go` as `ai.ToolExecutor`).
  - `ai/`: Providers (`gemini.go`, `openai.go`, `claude.go` on `anthropic-sdk-go`, OpenAI-compatible `custom`) + Edge neural TTS. `provider.go` is the registry (`DefaultModel()`, `ServerKeys`, models, `chatSession`). `chat.go` runs the tool loop over `ChatOptions.ToolExecutor` (≤ `MaxToolRounds`, last round without tools, retry without tools if rejected), streaming text + `[DONE]`. API keys in headers only; `custom` uses only the request key.
  - `storage/`: CGO-free SQLite (`modernc.org/sqlite`), migrations (`schema_version`), custom `MarshalJSON` sanitization, `zstd` lap BLOBs (`lap_telemetry` with `ON DELETE CASCADE`). **Session UIDs must always be stored/serialized as Hex strings** (`TEXT`, e.g., `0x...`).
  - `settings/`: Shared JSON settings (`settings.Sections`: `ai`, `voice`, `ptt`, `engineer`).
  - `locales/`: Type-safe `PromptCatalog`, registry (`Resolve`, `Get`), `en`/`es` catalogs (no boolean flags).
  - `input/`: Global PTT (`winmm.dll` DirectInput wheels, `user32.dll` keyboard on Windows; Gamepad API + `Space` fallback).
  - `system/`: Version metadata, GitHub update check (`system.DefaultGitHubRepo`), network discovery (`DescribeTelemetryEndpoint`), `OpenBrowser`.
  - `tsgen/`: Standard-library Go-to-TS wire type generator (`cmd/tsgen`).

### Wire Types & REST Contracts
* **Wire Types (`cmd/tsgen` → `frontend/src/types/generated/`):**
  - Generated per Go package from `cmd/tsgen/main.go`: REST responses, `ai.AIChatRequest` (`ChatContextMode`), `EngineerSocketMessage` (`EngineerDirective | PTTEventMessage | PTTLearnedMessage | PTTLearnTimeoutMessage | SettingsChangedMessage`, `SettingsSection`, `EngineerAlertKey`, `EngineerDirectiveCategory`, `EngineerUrgency`), `session.FeedEvent` (`FeedEventCode`, `FeedEventType`, `FeedSeverity`), `session.LiveSnapshot`. Never edit generated files or hand-copy wire types.
  - `internal/tsgen` uses `tstype:"..."`, `TypeAlias` (`[]map[string]any`), `Marshaler` (`MarshalJSON`, `TestMarshalerKeys`). Responses must be named structs, never `map[string]any`.
  - `types/*.ts` re-export generated types (`types/telemetry.ts`: `LapData`, `CarStatusData`, `CarDamageData`, `CarTelemetryData`, `CarTelemetry2Data`, `ParticipantData`, `SessionData`), narrow unions via `Narrows<T, Base>` (`types/wire.ts`), and tests use `test/wireFactories.ts` (`makeLive*`).
* **REST Errors & Client (`utils/apiClient.ts`):**
  - Non-OK responses return `{"error","code"}` (`internal/api/response.go`). Failed `POST /api/sessions/import` (400) sets `error` to first `details[].reason`. Batch export: `POST /api/sessions/export-batch` (`{"session_ids":[...]}`). Frontend calls REST only via `apiClient.ts` (`request()` → `ApiError.message`; `api.stream()` → raw `Response` for `sseUtils.ts`).

### Settings Ownership & Cross-Tab Sync
* **Server Settings (`GET`/`PUT /api/settings/{ai,voice,ptt,engineer}`):**
  - API keys are write-only. AI resolution: request → saved → env (`GEMINI_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `LLM_PROVIDER`, `LLM_MODEL`) → default (`internal/ai`). Startup: flags → env → `.env`.
  - **Engineer (`settings.Engineer` under `engineer_config`):** Stores `engineer.Tuning`, `trigger_preset`, `alert_switches` (`engineer.AlertSwitchKeys` → `EngineerAlertSwitch` vs `ALERT_TOGGLE_KEYS`), loaded over `settings.DefaultEngineer()`. `Engineer.EngineConfig()` builds runtime config via `engineer.EnabledCategoriesFromSwitches` (missing = on) + `engineer.DefaultEngineerConfig()`; browser never sends `EnabledCategories`/server constants and reads defaults from `GET /api/settings/engineer/defaults`.
  - **Concurrency & Sync:** Engineer PUTs carry `version`; server bumps it, returning `409` (`SETTINGS_CONFLICT`) on stale saves (UI reloads + notice). PUT decodes over saved setup and broadcasts `settings_changed` (`section`, `source` from `X-Dashboard-Client`, `version`) on `/ws/engineer`.
  - **Client Sync (`utils/settingsClient.ts`):** Saves via `putSettings(section, body)` (`DASHBOARD_CLIENT_ID`), listens via `subscribeSettingsChanges` (ignoring own tab): `SettingsSync.tsx`, `useAISettings`, `usePTTConfig` reload on change. Engineer saves debounce (`syncConfigToBackend()`). Failed saves report to `useSettingsSaveStore` (`reportSettingsSaveFailure`); never swallow errors.
* **Per-Device `localStorage` (`utils/storage.ts`):**
  - Only via `storage.ts` (`KnownStorageKey`): `RADIO_STORAGE_KEYS`, `f1_active_tab`, `f1_telemetry_dismissed_update`, `f1_telemetry_language`, `f1_live_view_mode[_phone]`, `f1_ai_engineer_{open,expanded}`, `f1_comparator_{rival_mode,rival_driver_name,chart_view,strip_layout}`, `f1_history_{group_by,saved_filters}`, migration keys (`LEGACY_RADIO_STORAGE_KEYS`, `f1_ai_engineer_config`, `f1_comparator_default_driver_name`).

### WebSockets, Live Telemetry & AI Chat
* **WebSockets (`utils/websocketClient.ts`):** Keep gorilla `CheckOrigin` (never override). `/ws` and `/ws/engineer` are ref-counted singletons via `createSharedSocket(path)` (`connectTelemetryWebSocket`, `subscribeEngineerMessages` in `utils/engineerSocket.ts`). `/ws/engineer` drops unknown types; server sends API events via `Server.broadcastEngineer` and directives via `EngineerEngine`.
* **Live Snapshot (`/ws`) & Status:** Only Live tab opens `/ws`; other pages poll `GET /api/system/status` (`api.SystemStatus`: UDP addr, `packet_age_ms`, session from `LiveBroadcaster.FeedStatus()`) via ref-counted `subscribeSystemStatus` (`useSystemStatusStore`; stale after 3s, listening after 60s). `useLiveStatus()` (`offline | listening | live | stale`) drives nav badge, header, title, `LiveSessionToast` (never show `"LIVE"` just because backend is reachable). UDP port/LAN IPs come from `GET /api/system/network` (`useTelemetryEndpointStore`; never hard-code 20777). `/ws` sends only 10 Hz `PacketIDLiveSnapshot` (255) DTO (`session.LiveSnapshot` in `internal/session/live_snapshot.go`: `ActiveCarCount` rows, live-view fields, filled forecasts, no marshal zones; checked by `TestLiveSnapshotPayloadSize`). Add new live fields to `Live*` + `toLive*` in `live_snapshot.go` and run `make gen-types` (never send raw packets). `GapAheadTrend`/`GapBehindTrend` (`LiveGapTrend`, ms/lap) come from `EngineerEngine.GapTrends()` (numbers behind the AI's trend text) via `SetGapTrendSource`; the store keeps `bestLapTimes` (`mergeBestLaps`) and the trends.
* **Race-Control Feed (`internal/session/feed_events.go`):** `LiveBroadcaster` turns Packet ID 3 + derived events (pit entry, penalty, retirement, DSQ, SC) into `session.FeedEvent` (`FeedEventCodes`, type, severity, typed params; no text), sent in `LiveSnapshot.Events` and `FeedEventSink` (`SessionManager.RecordFeedEvents`, stamping leader `RaceLap` in `session_events`). `utils/raceEvents.ts` formats `en`/`es` text via exhaustive switch on `FeedEventCode`.
* **AI Chat (`/api/ai/chat`):**
  - `POST /api/ai/chat` sends only IDs in `context` (`ai.ChatContextRequest`: `context_mode`, `session_id`, or `lap_a_id`/`lap_b_id`/`zoom`); browser never writes prompts/summaries. `ai.BuildChatContext` builds prompts on server (`LiveRaceSource`—omitted when stale—or `RecordedRaceSource` / `analytics.ChatContextSource`) + saved `DriverCallsign`/`CustomPrompt`, with driving phase / 2026 rules / incident status from engine briefing only; both unknown IDs (404) and bad context (400) return `INVALID_REQUEST`.
  - `RaceEngineerContextDefinitions.ts` splits `useRaceEngineerActions()` (stable ref callbacks), `useRaceEngineerState()` (window, URL targets via `chatTargetsFromRoute`, AI settings), `useRaceEngineerStream()` (messages) so pages never re-render per chunk (`App.rerender.test.tsx`).
  - SSE (`internal/ai/sse.go`, `utils/sseUtils.ts`) streams `data: {"text":...}` + `data: [DONE]`, or final `data: {"error","code","provider","message"}` frame (`aiErrorPayload` / `classifyAIError`), read via `readChatStream` and `chatStreamErrorFromResponse` (`ChatStreamError`; unanswered = `NETWORK_ERROR`). `POST /api/ai/models` returns filtered chat models; `ChatSettingsDrawer` uses `AI_SERVER_PRESETS`. Markdown renders via `utils/markdown.ts` + `components/ui/Markdown.tsx` (no raw HTML).

### Recorded Sessions, Player Car, Comparator, Progress & Routing
* **Session Detail & Cache:** `GET /api/sessions/{id}/detail` (`analytics.ComputeSessionDetail`, checked by `TestSessionViewPayloadSize`) loads session, participants, laps, `session_events` once. `participants`/`laps` are top-level (`DriverStanding`/`DriverStint` omit slices via `json:"-"` and join in `normalizeDriverStanding`). `sessionDataCache.ts` caches ≤ `SESSION_DATA_CACHE_LIMIT` sessions (`useSessionDetail` primes; comparator shares `getSessionLapData`; delete/import invalidates).
* **Story & Stints:**
  - Detail tabs: `story | classification | pace | position | gap | stints | sectors` (`SESSION_DETAIL_TABS`; `RACE_CHART_TABS` for races). `analytics.RaceControlPeriods` + `utils/raceStory.ts` (`raceControlPeriods`, `keyMoments`, `momentsByLap`, `fieldPace`) power `SessionStoryTab` (`YourRaceCard`, `FieldPaceChart`, `SessionDebriefPanel`, `KeyMomentsTimeline`) + SC/VSC shading (`raceControlAreas`).
  - `ComputeSessionStints` fits OLS `degradation_slope` (≥3 clean laps) + `avg_lap_time_ms` after `stintExclusions` (`pit_in`/`pit_out` via `analyzeDriverLapOutliers`, `sc`/`vsc` via `neutralisedLaps`, `slow` > 107% of remaining median; stored at `{key}_excluded`/`{key}_reason`). `DegradationCurves.tsx` plots excluded laps as hollow dots, y-range capped at 107% of the median.
* **Player Car & Session List:**
  - `sessions.player_car_index` + `player_car_source` (`'game' | 'user' | null`) store player car (`saveSession` never overwrites `'user'`). `PUT /api/sessions/{id}/player` sets/clears car; `POST /api/sessions/batch-player` matches `Participant.DisplayName()` case-insensitively (`{updated, not_found, ambiguous}`). `GET /api/sessions` returns `SessionListItem` with `summary` (`leader`, `fastest_lap`, `laps_completed`, `player` via `FindPlayerStanding`).
  - Client: `utils/player.ts`, `PlayerPickerModal`, `BatchDriverModal`, `utils/sessionListView.ts`, `useSessionListPaging` (50 per page). `getTrackInfo` matches exact names/aliases before substrings.
* **Comparator & Progress:** Defaults use `resolveReferenceLap` (Slot A: `player_car_index` with fastest-lap fallback) + `resolveComparisonLap` (Slot B: `f1_comparator_rival_mode` / `f1_comparator_rival_driver_name`), `comparatorQuickStart.ts`, `CornerTable.tsx` (`analyzeCorners` in `utils/trackTurns.ts`, syncing URL `zoom` + AI chat), `StripCharts.tsx` (`stripTraces.ts`, `normalizeStripLayout`). `GET /api/progress?track=` (`ComputeTrackProgress`) powers `/progress[/:track]` (`useTrackProgress`, `progressStats.ts`), returning `ProgressTracks`, `ProgressSession` (`consistency_ms`: std dev of ≥ `MinConsistencyLaps` clean laps), `unmatched_sessions`.
* **URL Routing (`router/`):** History API router in `routes.ts` (`parseRoute`, `buildPath`, `useRoute()`, `navigate()`, `Link`): `/history`, `/history?quick=&track=` (`Route.listFilter`, applied once then replaced by `/history`), `/history/:sessionId[/:tab]` (`story` if omitted; `/charts` → `pace`), `/compare?sa=&a=&sb=&b=&zoom=`, `/progress[/:track]`, `/live/:mode` (`dashboard` | `cockpit` | `driver`). `/` reopens last page, `/live` last live mode (phones keep their own, default `driver`: `DriverGlance`, `useScreenWakeLock`), unknown paths → `/history`. New pages/sessions push history; within-page changes (detail tab, comparator laps/zoom, live mode) `replace` it. Add new routes to `routes.ts`, its tests, `TestHandleEmbeddedFrontendAndSPAFallback`.

## 4. F1 Telemetry & Radio Protocols
* **Proactive Radio:** Directives on `/ws/engineer` carry `sub_alert` (`engineer.RadioAlertKeys`, checked by `TestRadioAlertKeys_MatchWhatTheEngineEmits`), category, urgency, no wire text (`Title`/`Message` stay on server). UI maps `EngineerAlertKey` (`constants/radioAlertCategories.ts`) and picks persona phrase from `locales/{en,es}/radio_phrases.ts` (`getProactiveRadioSpeech`). Driver PTT uses `[DRIVER RADIO TRANSMISSION]` (`useRadioAudio.ts`); `cleanRadioSpeechText` strips bracketed tags before TTS. **Never use acknowledgement openers ("Entendido" / "Copy" / "Roger") on proactive calls** (only on PTT replies). Address driver in 2nd person.
* **Phase Lifecycle & Audio (`DrivingPhase`):** `PhaseFlyingLap` (only lap invalidations + `UrgencyCritical`), `PhaseGrid` & `PhaseRaceStart` (only critical SC or terminal damage), `PhaseInGarage` & `PhasePitLane` (only strategic garage/pit alerts; silence non-critical calls while stationary in box or pit limiter on), `PhaseOutLap` & `PhaseInLap` (out-lap: thermal prep, clean air, traffic; in-lap: cooldown, battery harvest, yielding). `useTTSPlayback.ts` queues non-critical calls sequentially (`UrgencyCritical`/`UrgencyHigh` preempt); streamed PTT replies play per sentence (`createSentenceChunker`, `beginReplyStream()`). Enforce `GlobalRadioChatterCooldownMs = 4_000`, steward penalties superseding corner-cutting warnings, SC/VSC/yellow shield (`0.35s <= delta <= 3.0s`), `flags_rain_live` / `tyre_crossover` grip calls.

## 5. UI/UX, Design Tokens & Accessibility
* **Design Tokens (`styles/base/variables.css` & `theme.ts`):** `variables.css` defines `--bg-*`, `--text-primary|body|secondary|muted` (≥ 4.5:1 contrast), `--accent-*`, `--status-*`, `--f1-*`, `--weather-*`, `--chart-*`, spacing, typography, radius, shadows, `--z-*` (`nav < docks < popovers < dialogs < toasts < tooltips`), motion. Never use raw color literals in components. TS reads tokens only via `styles/theme.ts` (`cssVar`, `getCssVars`, `alpha`, `canvasRgba`, `styleVars`, `THEME_TOKENS` checked by `theme.test.ts`; never append hex alpha like `${color}40`). Use `TYRE_COMPOUNDS` / `getVisualCompoundId`, `getTeamColor(teamId)` (`constants/f1.ts`), `CHART_COLORS` (`chartDefaults.ts`).
* **Accessibility & Primitives (`styles/base/accessibility.css`, `components/ui/`):**
  - Global `:focus-visible` ring (`--focus-ring-color`; only text fields drawing own focus state may set `outline: none`), `.sr-only`, `prefers-reduced-motion` (`prefersReducedMotion()` in `utils/motion.ts`). Clickables must be `<button>` (`.button-reset`) or `Link` with ARIA state (`aria-pressed`, `aria-expanded`, `aria-selected`, `aria-current`, `aria-sort` on `<th>`; clickable rows/cards/backdrops keep `onClick` only as `role="presentation"` shortcut for a real button). Color is never sole cue (`SectorTime.tsx`). Toasts use always-mounted `aria-live="polite"` region (`role="alert"` for errors).
  - Reuse `components/ui/` (`Button`/`IconButton`, `Modal`, `Menu` + `roving.ts`, `Panel`, `Badge`, `Tabs`, `SegmentedControl`, `DataTable`, `Stat`, `Switch`, `Slider`, `TextInput`/`TextArea`/`Select` in `Field.tsx`, `EmptyState`, `Skeleton`, `Tooltip`/`useTooltip`, `Markdown`, `useDialogLayer`, `cx.ts`) with CSS Modules (`Name.module.css`).
  - **Breakpoints:** `@media (--phone)` (≤600px), `(--tablet)` (≤900px), `(--laptop)` (≤1100px) from `styles/breakpoints.ts` (`breakpointMedia` in `vite.config.ts`, enforced by `breakpoints.test.ts`) or `useMediaQuery(maxWidth(...))`. Prefer roles, labels, `data-*` attributes over CSS class names in tests.

## 6. Multi-Language, CI/CD & Documentation
* **Localization:** `locales/en/` is base schema. Backend (`internal/locales`) uses `PromptCatalog` (`EnglishCatalog`, `SpanishCatalog`), thread-safe `Resolve`/`Get`, Edge Neural TTS voice mappings without boolean flags. Frontend `I18nProvider` (`context/I18nProvider.tsx`) + `useI18n` (`context/I18nContext.tsx`) support `en` (🇬🇧) and `es` (🇦🇷 `"Español (Latinoamérica)"`), persisted via `LanguageSelector.tsx` (`f1_telemetry_language`).
* **CI & Docs:** Integrate new tests, generators, or linters in `.github/workflows/ci.yml`. Update docs when architecture, CLI flags, or features change: keep `README.md` user/contributor-facing, and keep internal invariants/rules in `.agents/AGENTS.md` (`< 20 KB` so `<user_rules>` never truncates).
